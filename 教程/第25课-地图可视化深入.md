## 1.1 两个"高德":JS API 画图,MCP 查数

第 1 课 1.3 节埋过一个伏笔:项目里高德出现了**两次**。现在你已经有足够上下文把它们彻底讲清楚。

**后端:amap-mcp-server,负责"查数"。** `trip_planner_agent.py:168-175` 创建的 `MCPTool` 通过 stdio 拉起 `uvx amap-mcp-server` 子进程,Agent 用它查 POI、天气、路线——这些数据进入 LLM 的提示词,最终写进 `TripPlan`。它的 Key 是**服务端 Key**,只存在于 `backend/.env`(`AMAP_API_KEY`),永远不会出现在浏览器里。

**前端:高德 JS API,负责"画图"。** `Result.vue:315` 引入官方加载器:

```ts
import AMapLoader from '@amap/amap-jsapi-loader'   // Result.vue:315
```

它把高德的地图渲染 SDK 加载进浏览器,用 `TripPlan` 里的坐标画 Marker 和 Polyline。它的 Key 是**Web 端(JS API)Key**,来自 `frontend/.env` 的 `VITE_AMAP_WEB_JS_KEY`——注意 `frontend/.env.example:5-7` 里其实留了两个 Key(`VITE_AMAP_WEB_KEY` 和 `VITE_AMAP_WEB_JS_KEY`),本项目的地图代码只用到了后者。

**为什么要分两个 Key?** 因为两者的安全模型完全不同:

| | 后端 MCP 服务 | 前端 JS API |
|---|---|---|
| 谁持有密钥 | 只有服务器(.env) | **浏览器里人人可见**(DevTools 就能看到) |
| 高德的保护手段 | 密钥保密 | Key + **安全密钥**(securityJsCode)+ 域名白名单 |
| 用途 | 查数据(POI/天气/路线) | 渲染地图(标记/路线/视野) |

正因 JS API Key 必然暴露在浏览器,高德从 2021 年 12 月起新申请的 Key 要求配套**安全密钥**:在调用 `AMapLoader.load` **之前**设置 `window._AMapSecurityConfig = { securityJsCode: '你的安全密钥' }`。本仓库代码没有配置这一段——如果你的 Key 是之后申请的且地图加载报 `INVALID_USER_SCODE` 类错误,这就是原因;具体配置方式以高德官方文档「JS API 安全密钥」一节为准,那页还讲了通过 nginx 转发 `_AMapService` 的更安全的代理方案(第 30 课部署 nginx 时可以回头看)。

**分工记忆:** MCP 给"大脑"喂数据,JS API 给"眼睛"画界面。Agent 规划出的坐标是两者之间唯一的桥梁——`TripPlan` 里每个景点的 `location`,既是 LLM 查询的产物,又是画图的原料。

## 1.2 地图初始化三步:Loader → 实例 → 覆盖物

地图的全部入口是 `initMap`(`Result.vue:790-813`):

```ts
// 初始化地图
const initMap = async () => {                                  // 790
  try {
    const AMap = await AMapLoader.load({                       // 792
      key: import.meta.env.VITE_AMAP_WEB_JS_KEY,               // 793  高德地图Web端(JS API) Key
      version: '2.0',                                          // 794
      plugins: ['AMap.Marker', 'AMap.Polyline', 'AMap.InfoWindow']  // 795
    })

    // 创建地图实例
    map = new AMap.Map('amap-container', {                     // 799
      zoom: 12,
      center: [116.397128, 39.916527], // 默认中心点(北京)     // 801
      viewMode: '3D'
    })

    // 添加景点标记
    addAttractionMarkers(AMap)                                 // 806

    message.success('地图加载成功')                             // 808
  } catch (error) {
    console.error('地图加载失败:', error)
    message.error('地图加载失败')
  }
}
```

逐行拆解,有三个值得注意的细节:

**① plugins 是按需加载。** 高德 JS API 2.0 的核心包很小,Marker、Polyline、InfoWindow 这些"插件"按需声明、按需下载。`795 行`的数组就是本项目用到的全部三种覆盖物——本课实验不会用到第四种,这个清单不用改。

**② `import.meta.env` 是构建期替换。** `793 行`的 Key 不是运行时读取的:Vite 在打包时把 `import.meta.env.VITE_AMAP_WEB_JS_KEY` 直接替换成字符串常量。这个事实在第 30 课 Docker 化时会变成一个真实的坑(构建镜像时不传这个变量,地图就永远空白)。

**③ 初始中心点是写死的北京(`801 行`),但用户可能去任何城市。** 为什么没出问题?因为后面 `addAttractionMarkers` 里的 `map.setFitView(markers)`(`873 行`)会自动把视野调整到包含全部 Marker——写死的初始中心只是"渲染瞬间的一帧"。这是地图开发常见套路:**先给个兜底视野,再用数据适配覆盖。**

还要看清调用时机。`onMounted`(`329-339 行`)的顺序是:从 `sessionStorage` 读 `tripPlan` → 加载景点图片 → `await nextTick()`(等 DOM 渲染完成,`#amap-container` 必须真实存在,`799 行`才能找到它)→ `initMap()`。而编辑模式保存时(`363-378 行`)会先 `map.destroy()` 再重建——**地图是"销毁重建"而不是"增量更新"**,这个粗暴但有效的做法,正是"数据是唯一事实来源"思想的体现。

## 1.3 Marker 与 InfoWindow:让每个景点"可点"

`addAttractionMarkers`(`Result.vue:816-878`)分三步:收集 → 建标记 → 建信息窗。

**第一步,收集所有带坐标的景点(823-833 行):**

```ts
tripPlan.value.days.forEach((day, dayIndex) => {
  day.attractions.forEach((attraction, attrIndex) => {
    if (attraction.location && attraction.location.longitude && attraction.location.latitude) {
      allAttractions.push({ ...attraction, dayIndex, attrIndex })
    }
  })
})
```

注意两点:每个景点被附加了 `dayIndex` 和 `attrIndex` 两个索引,后面 InfoWindow 和本课实验都靠它们做"数据↔UI"的映射;**缺坐标的景点会被静默丢弃**——这正是第 16 课给规划链路接 `geocode` 兜底的直接收益:没有真实坐标,景点不但数据上是残缺的,连地图上都"不存在"。

**第二步与第三步,创建标记和信息窗(836-866 行):**

```ts
allAttractions.forEach((attraction, index) => {
  const marker = new AMap.Marker({
    position: [attraction.location.longitude, attraction.location.latitude],
    title: attraction.name,
    label: {
      content: `<div style="background: #4CAF50; ...">${index + 1}</div>`,   // 841
      offset: new AMap.Pixel(0, -30)
    }
  })

  const infoWindow = new AMap.InfoWindow({                                   // 847
    content: `
      <div style="padding: 10px;">
        <h4 ...>${attraction.name}</h4>
        ...
        <p style="margin: 4px 0; color: #1890ff;"><strong>第${attraction.dayIndex + 1}天 景点${attraction.attrIndex + 1}</strong></p>
      </div>
    `,                                                                        // 848-856
    offset: new AMap.Pixel(0, -30)
  })

  marker.on('click', () => {                                                 // 861
    infoWindow.open(map, marker.getPosition())
  })

  markers.push(marker)
})

map.add(markers)                                                             // 869

if (allAttractions.length > 0) {
  map.setFitView(markers)                                                    // 873
}
```

这里有三个值得停下来想 30 秒的点:

1. **编号体系不一致。** Marker 的 label 用的是**全局序号** `index + 1`(`841 行`,跨天连续 1、2、3…8),而右侧日程卡片上的角标用的是**当天序号**(`template` 里 `{{ index + 1 }}`,`195-196 行`),InfoWindow 里又是"第 X 天 景点 Y"(`854 行`)。三套编号并存,用户对着地图上的"6"找不到卡片上的"2"。本课实验会顺手统一它。
2. **InfoWindow 的 content 是拼接的 HTML 字符串。** `attraction.name`、`attraction.description` 都是 LLM 生成、未经转义的内容,直接插进 HTML。第 22 课讲提示词注入时你见过"数据不可信"这个命题——它对前端同样成立(恶意或失控的 LLM 输出可以往 InfoWindow 里塞脚本)。这里的现实风险很低(数据来自自己的后端),但**知道这里有个注入口**是本课的隐藏教学目标。
3. **闭包的正确用法。** 每个 `marker.on('click')` 的回调都捕获了各自的 `infoWindow` 和 `marker`——这是 861 行能正常工作的原因,也是你第 4 课学过的闭包知识在真实代码里的样子。

## 1.4 Polyline:把"每天的路线"画出来

`drawRoutes`(`Result.vue:881-913`)先按天分组,再每天画一条线:

```ts
const drawRoutes = (AMap: any, attractions: any[]) => {
  if (attractions.length < 2) return

  // 按天分组绘制路线
  const dayGroups: any = {}                               // 885
  attractions.forEach(attr => {
    if (!dayGroups[attr.dayIndex]) {
      dayGroups[attr.dayIndex] = []
    }
    dayGroups[attr.dayIndex].push(attr)
  })

  Object.values(dayGroups).forEach((dayAttractions: any) => {
    if (dayAttractions.length < 2) return

    const path = dayAttractions.map((attr: any) => [
      attr.location.longitude,
      attr.location.latitude
    ])

    const polyline = new AMap.Polyline({                  // 902
      path: path,
      strokeColor: '#1890ff',
      strokeWeight: 4,
      strokeOpacity: 0.8,
      strokeStyle: 'solid',
      showDir: true // 显示方向箭头
    })

    map.add(polyline)                                     // 911
  })
}
```

功能是对的,但有两个"半成品"痕迹:

1. **所有天的线都是同一个蓝色**(`904 行`),多日行程在地图上分不出哪条线属于哪天;
2. **`polyline` 创建后被 `map.add` 就丢了**——没有保存任何引用。Marker 数组好歹还留到了 `setFitView`,Polyline 连这个待遇都没有。

引用丢了意味着:**画完之后,代码再也无法操纵这条线**——不能隐藏它、不能改色、不能删除。这就是本课实验要解决的核心问题。

另外值得知道:这些折线是**景点间直线**(按游览顺序连点),不是真实道路。真实路网数据你的后端其实已经有能力拿(第 16 课的 `plan_route`),如何用路网坐标画真实路线,留作选做作业。

## 1.5 覆盖物的生命周期:图层管理思维

把 1.2–1.4 的观察收敛成三条通用原则——它们适用于任何地图库(高德、Leaflet、Mapbox):

**原则一:凡 add,必存引用。** `map.add()` 返回或传入的覆盖物对象,要按业务维度存起来。存什么维度?由你想要的**操作粒度**决定:想"按天隐藏"就按天存,想"点击路线高亮"就按景点存。本实验按天存:

```ts
type DayLayer = { markers: any[]; polyline: any | null }
const dayLayers: Record<number, DayLayer> = {}
```

**原则二:show/hide 是"软操作",remove/add 是"硬操作"。** `marker.hide()/show()` 不销毁对象、瞬间生效,适合频繁切换图层;`map.remove()` 才真正删除。切天视图这种高频交互,用软操作。

**原则三:重建数据时,先清场。** 现在 `saveChanges` 用 `map.destroy()` 整图销毁再重建(`371-378 行`),清场是彻底的。但如果你以后把"重建"优化成"增量更新"(比如只删掉被移除的景点),就必须先 `remove` 旧覆盖物——否则它们会变成"幽灵点":数据里没有,地图上还在。**幽灵覆盖物是地图开发最经典的 Bug 来源。**

## 1.6 动手实验:按天图层切换 + Marker 联动日程卡片

### 任务

在地图卡片上加一排"第 1 天 / 第 2 天 / …"的切换控件:勾选哪天,就显示哪天的 Marker 和路线;点击某天的 Marker,右侧"每日行程"自动**展开并滚动**到对应面板。

### 步骤

1. **准备状态。** 在地图组件(或 `Result.vue` 的 `<script setup>`,`327 行`附近)新增:

   ```ts
   const visibleDays = ref<Record<number, boolean>>({})   // 每天是否可见,默认全 true
   const dayLayers: Record<number, { markers: any[]; polyline: any | null }> = {}
   ```

2. **改造 `addAttractionMarkers`(816 行)。** 收集景点时(`823-833 行`)顺便初始化 `dayLayers[dayIndex] = { markers: [], polyline: null }` 和 `visibleDays.value[dayIndex] = true`;创建 Marker 时把 `841 行`的全局 `index + 1` 改成当天序号 `attraction.attrIndex + 1`(与卡片角标一致);每个 marker 在 `869 行`的 `map.add` 之外,**再 push 进 `dayLayers[attraction.dayIndex].markers`**。

3. **改造 `drawRoutes`(881 行)。** 在 `911 行` `map.add(polyline)` 后保存引用:

   ```ts
   dayGroups 的 key 就是 dayIndex,循环时拿到它(用 Object.entries 替代 Object.values):
   dayLayers[dayIndex].polyline = polyline
   ```

4. **实现图层开关。** 新增一个函数,并让控件触发它:

   ```ts
   const applyDayFilter = () => {
     Object.entries(dayLayers).forEach(([dayIndex, layer]) => {
       const show = visibleDays.value[Number(dayIndex)]
       layer.markers.forEach(m => (show ? m.show() : m.hide()))
       if (layer.polyline) (show ? layer.polyline.show() : layer.polyline.hide())
     })
   }
   ```

   UI 放在地图卡片头部(模板 `113 行`附近),用 `a-checkable-tag` 或 `a-checkbox-group` 渲染 `tripPlan.days` 的每一天,`v-model` 绑 `visibleDays`,change 时调 `applyDayFilter()`。

5. **实现 Marker → 卡片联动。** 在 `861-863 行`的 click 回调里,打开 InfoWindow 之后追加:

   ```ts
   marker.on('click', () => {
     infoWindow.open(map, marker.getPosition())
     activeDays.value = [attraction.dayIndex]        // 第 121 行是 accordion 折叠面板,展开当天
     nextTick(() => {
       document.getElementById(`day-${attraction.dayIndex}`)
         ?.scrollIntoView({ behavior: 'smooth', block: 'start' })
     })
   })
   ```

   为什么可行:每日行程的 `a-collapse-panel` 已经带 `id="day-${index}"`(模板 `125 行`),而 `activeDays` 就是折叠面板的 `v-model:activeKey`(`121 行`,`326 行`定义,accordion 模式同时只开一天)。先展开、`nextTick` 等 DOM 更新、再滚动——这个三步节奏和 `onMounted` 里"等 DOM 再 initMap"(`335-337 行`)是同一个道理。注意 `346-352 行`现成的 `scrollToSection` 只滚动不展开,不能直接复用。

6. **验证重建场景。** 进编辑模式 → 删一个景点 → 保存(`371-378 行`会 destroy 重建地图)→ 确认图层切换和联动依然正常。

### 完成标准

- [ ] 地图卡片上出现"第 1 天/第 2 天/…"切换控件,取消勾选后该天的 Marker **和** Polyline 同时消失,重新勾选恢复;
- [ ] 点击某天任一 Marker:右侧对应 Collapse 面板自动展开并平滑滚动到视野内(配合 InfoWindow 一起出现);
- [ ] Marker 编号与日程卡片角标一致(都是当天序号);
- [ ] 编辑保存触发地图重建后,上述功能全部正常(说明引用随重建刷新了);
- [ ] 只有 1 个景点或某天只有 1 个景点时,一切照常不报错(`882 行`和 `895 行`的长度保护还在)。

### 常见卡点

- **"隐藏几天之后,setFitView 的视野还是把隐藏的 Marker 算进去了?"** —— `setFitView` 不理会覆盖物的 show/hide 状态,它按你传的数组算。想让视野跟随可见图层,在 `applyDayFilter` 末尾收集所有可见 marker 再调一次 `map.setFitView(visibleMarkers)`。
- **"点击 Marker 报 `Cannot read properties of null`?"** —— 八成是组件化后的作用域问题:`327 行`的 `let map: any = null` 原本是模块级变量,拆进组件后它必须在组件实例(或 composable)的作用域里;如果 click 闭包捕获的是旧一次 initMap 的局部变量,重建地图后旧引用已 destroy。
- **"联动滚动的位置差半屏?"** —— `block: 'start'` 会把面板顶到视口最上面,被固定的页头挡住。给 `scrollIntoView` 换成 `scrollIntoViewOptions` 的 `block: 'center'`,或用第 24 课学过的 `scroll-margin-top` CSS 属性给面板留出头部空间。
